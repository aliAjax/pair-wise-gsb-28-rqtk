# 配送任务拖拽排班（发车后改派受控）

- 行业：物流
- 技术栈：React 19、Vite、TypeScript、Ant Design、dnd-kit、zustand
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

## 业务闭环

- 订单含**送达时段、冷链标记、重量**；车辆绑定**司机、班次时段、温区（常温/冷藏）、载重**。
- 待分配订单拖入车次即排班；拖入时按 **温区 / 送达时段是否落在班次内 / 载重** 校验，任一不符**整次拒绝、不动布局**，并在车次卡上标出冲突字段（时段冲突、温区冲突、载重冲突）。
- 已排车次在发车前可调整停靠顺序、摘回待分配池、换车。
- **发车即锁**：停靠顺序、司机、温区不可变；不能再摘回或拖入，只能改派。
- **发车后改派必须先建交接单**：记录原车、新承接车辆、未送订单快照。
  - 待生效：**原车占用不释放**（订单仍在原车次），新承接车次为冻结占位，**未生效不得装货、不能发车**。
  - 生效：未送订单转移到新车并自动发车，原车占用此刻才释放（途中已送达的订单留在原车）。
  - 作废：删除冻结占位车次，原车占用自始未释放。
- 页面三栏：**待分配 / 已排车次 / 运输中·已完成**，附交接链台账；重载后车次、占用与交接链仍对应（localStorage 持久化 + 跨标签页同步）。

## 分层落位

- `src/data/`：数据层 —— `types.ts` 领域模型、`seed.ts` 种子数据与 localStorage 仓储、`store.ts` zustand 唯一写入入口。
- `src/rules/dispatch.ts`：规则层 —— 纯函数（排班校验、发车锁定、交接单状态机、占用计算、交接链查询），不依赖 React。
- `src/views/`：视图层 —— `Board`（dnd-kit 三栏看板）、`TripCard`、`OrderCard`、`HandoverModal`、`NewOrderModal`、`HandoverLedger`、`Metrics`。

所有写操作先过规则校验，校验不通过 store 不改状态，因此拒绝时布局保持不动。
